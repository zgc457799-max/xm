## 第一章 需求分析
在程序设计教育领域，传统在线评测系统（OJ）暴露出以下痛点：一是教师的讲义和测试案例难以快速转化为结构化的自动评测题库；二是导学反馈弱，系统仅冰冷地返回“Wrong Answer”或晦涩的底层报错代码，缺乏对学生解题思维的启发；三是学情建模浅薄，仅靠分数无法精准刻画学生在具体知识点（如指针、递归）上的掌握程度，导致教学干预滞后。

针对这些痛点，我们开发了“EduCode AI一站式在线编程辅助教学系统”。本项目创新性地将大语言模型（LLM）与 Docker 容器化沙箱深度融合。主要面向高校编程初学者与计算机专业教师。通过内置的“代码感知型AI助教”，系统能够捕获沙箱底层的报错日志并为学生提供秒级启发式纠错；此外，系统结合了基于 WebGL 的 3D 星盘通关与宠物养成等游戏化机制，极大降低了初学者的畏难情绪。相比于传统竞品（如洛谷、PTA），EduCode 在安全性、智能启发反馈与沉浸式交互体验上具有显著的代际优势。

## 第二章 概要设计
本系统采用前后端分离与微服务架构：
1. **表现层 (Frontend)**：基于 React 19 + Vite 构建，集成 TailwindCSS 提供现代化 UI，使用 Monaco Editor 作为核心代码编辑器，并通过 `@react-three/fiber` 渲染 WebGL 3D 交互宠物与星盘。
2. **业务网关层 (Backend)**：采用 Node.js + Express 处理 RESTful API，结合 Socket.IO 实现高并发双向实时通信与全站广播。
3. **核心引擎层 (Core Engines)**：
   * **判题沙箱引擎**：底层基于 Docker 引擎，通过容器虚拟化技术实现代码执行的时空绝对隔离。
   * **AI 导学引擎**：通过接入大语言模型（LLM）接口，处理代码上下文和错误日志。
   * **语音引擎**：集成 Edge TTS 实现虚拟宠物的多声线语音交互。
4. **数据层 (Database)**：采用 MySQL 8.0 持久化结构数据，Redis 作为内存级高速缓存保障排行榜与队列的高效读取。

## 第三章 详细设计

### 3.1 关键核心技术与创新点
本项目在详细设计上的最大难点与创新点在于**“高并发安全判题”**与**“AI深度融合交互”**：
1. **Docker 安全隔离沙箱技术**：为防止学生提交的恶意代码（如死循环、删库、系统调用攻击）破坏服务器宿主机，我们在 Node.js 后端设计了动态容器调度队列。每次收到提交时，系统会生成临时 Docker 容器，并挂载代码文件。使用 Linux底层资源隔离配置严格限制其运行内存与 CPU 执行时间。程序一旦运行结束或超时，容器立刻自毁，确保了极高的安全性。
2. **代码感知型多模态 AI 助教**：我们不仅把大模型作为一个对话框，而是将其深深嵌入工作流中。当代码发生 `RE` (运行错误) 时，系统会自动截取 Docker 内部的标准错误输出堆栈，连同用户的源码一并发送给大模型（DeepSeek / Trae 等），要求 AI 以“启发者”而非“解答者”的身份给出中文代码逻辑引导，并通过 TTS 输出拟人化语音，极大提高了排错效率。
3. **WebGL 3D 数据可视化与游戏化渲染**：使用 Meshy.ai 生成高质量的 GLB 3D 模型资产（如科幻徽章、虚拟海狸宠物），并在前端使用 Three.js 进行渲染与光影调节。结合物理射线投射（Raycaster）实现用户与 3D 宠物的鼠标互动微动效。

### 3.2 数据库设计概要
系统基于关系型规范设计（3NF），核心实体包括：
* **Users（用户表）**：存储账号、多维能力雷达数据、当前积分与 Streak 连击天数。
* **Problems（题库表）**：存储题目 Markdown 描述、时空复杂度限制以及测试数据用例的 JSON 配置。
* **Submissions（提交记录表）**：记录用户提交源码、Docker 返回的执行状态码（AC/WA/TLE/RE）以及 CPU耗时与内存占用。
* **Mistakes（错题本表）**：基于提交记录自动归档未通过的题目，便于 AI 后续制定复习计划。

## 第四章 测试报告

### 4.1 主要测试过程与技术指标
为保障系统在教学场景下的健壮性，我们进行了严格的多维度测试：
1. **安全性与隔离测试**：我们专门编写了包含“Fork炸弹”、“内存泄漏（无限递归）”、“越界写文件”等恶意 C/C++ 脚本进行提交测试。结果表明：Docker 判题引擎均能在毫秒级成功拦截，精准返回 `TLE` 或 `RE` 状态码，宿主服务器资源监控无任何异常波动，安全性指标达标。
2. **AI 接口并发与降级测试**：测试在大批量学生同时发起 AI 求助时的情况。系统成功通过 Redis 令牌桶算法实现了 API 限流；在第三方大模型接口偶发性超时的情况下，前端平滑降级，提示用户稍后重试，不影响核心判题功能。
3. **前端渲染性能测试**：在包含 3D 星盘与高精度 GLB 宠物的场景下进行帧率监控，通过降低移动端 DPR (设备像素比) 与关闭抗锯齿，成功使低端核显笔记本的渲染帧率稳定在 60 FPS，可用性与可扩展性优异。

## 第五章 安装及使用

### 5.1 环境要求与安装配置
* **后端依赖**：Node.js v18+，MySQL 8.0+，Redis 4.0+，以及**必须在宿主机上安装并启动 Docker Desktop (或 Docker Engine)**，这是运行判题沙箱的核心。
* **前端依赖**：Node.js v18+ (使用 npm 或 pnpm)。

**部署流程**：
1. **数据库初始化**：导入 MySQL 脚本建表并执行后端 `npm run seed` 注入基础题库。
2. **后端启动**：进入 `server` 目录，执行 `npm install` 安装依赖，配置 `.env` 填入数据库密码与大模型 API Key。执行 `npm run dev` 启动网关与 WebSocket 服务。
3. **前端启动**：进入前端目录，执行 `npm install` 后，运行 `npm run dev` 启动本地 Vite 热更新开发服务器。
4. **沙箱前置验证**：务必确认 Docker 引擎图标显示为绿色运行状态，系统方可成功派发判题任务。

### 5.2 典型使用流程
学生注册登录 -> 进入首页查看个人的能力雷达与排行榜 -> 点击进入“星盘关卡”挑选题目 -> 在 Monaco 在线编辑器中编写代码 -> 点击“运行测试”（后端分配 Docker 沙箱并在数秒后通过 WebSocket 返回结果） -> 如果判题失败，点击“呼叫AI助教” -> AI 结合报错日志语音播报纠错建议。

## 第六章 项目总结
在本作的开发周期中，我们完成了从传统“静态评测”向“AI驱动动态导学”的跨越。
* **克服的困难**：最初面临的最大挑战是判题沙箱的搭建与多语言隔离的实现。我们阅读了大量底层文档，最终通过 Docker 容器的 API 挂载技术与资源限制完美解决了安全与并发难题。同时，在引入 3D 模型时，我们利用了前沿的 Meshy.ai 大幅度缩减了美术制作周期，并攻克了 WebGL 渲染的帧率优化难关。
* **水平提升**：团队成员不仅掌握了全栈 React+Node 的开发流，更深入理解了云计算底层的容器化技术与 LLM 提示词工程的应用。
* **演进与推广**：未来，我们计划进一步引入知识图谱技术，实现根据错题本自动为学生生成“千人千面”的阶段性练习试卷，并逐步在校内计算机导论课程中投入试运行，替代现有的传统机考系统。
